# CLAUDE.md — 프로젝트 상시 맥락 및 작업 규칙

> 이 파일은 Claude Code가 세션 시작 시 자동으로 읽는다.
> 여기 적힌 환경 제약과 규칙을 **모든 파일 생성·수정·명령 실행 시 항상 준수**한다.

---

## 1. 실행 환경 (반드시 인지)

- **기기**: NVIDIA Jetson (arm64 / aarch64, Ubuntu). x86 아님.
- **저장소 구성**:
  - `/` (eMMC, 28G) — **거의 가득 참(94%, 여유 약 1.8GB · 2026-10-12).** 시스템·실행 파일 전용.
  - `/mnt/ssd` (NVMe, 458G) — **여유 충분. 모든 작업물·데이터·프로젝트는 여기에 저장.**
- **이 프로젝트의 루트**: `/mnt/ssd/projects/myproject/`
- 홈의 `~/.cache`, `~/.claude`는 이미 SSD로 심볼릭 링크되어 있음.

### 작업 방식: 노트북 → VS Code Remote-SSH (2026-10-12부터)
- 보드에 모니터를 연결해 작업하지 않는다. **노트북 VS Code에서 Remote-SSH로 보드(`jetson`)에 접속**해 작업한다.
  Claude Code 세션도 이 원격 환경에서 돈다. 보드 화면(데스크톱)은 보지 않는다고 가정한다.
- 노트북 `~/.ssh/config`에 `Host jetson`(사용자 `wjs`) + **`LocalForward 8000 localhost:8000`** 터널이 있다.
  → **UI 확인은 노트북 브라우저 `http://localhost:8000/`** (의료진: 간호사 `?nurse=1`(예전 `?admin=1` 호환) · `?doctor=1` · `?callboard=1`).
  보드 IP는 폰 핫스팟이라 바뀔 수 있다(노트북 쪽 설정·문제 해결은 HANDOFF.md 0-10절).
- VS Code 서버는 **SSD `/mnt/ssd/vscode-server`**에 설치돼 있다(약 1.6GB). eMMC의 `~/.vscode-server`에는
  잠금·로그 파일만 있다 — 여기에 큰 파일이 쌓이지 않게 한다.
- **서버는 tmux 세션 `kiosk`에서 `./scripts/start_voice_ui.sh`로 돈다**(UI + STT + TTS, 로봇 주행 없음).
  - 확인: `tmux ls` · 로그만 보기: `tmux capture-pane -pt kiosk | tail -30` · 들어가기: `tmux attach -t kiosk`(빠지기 `Ctrl+B` `D`)
  - 수정 후 반영: **화면 파일(`src/`) = 브라우저 새로고침**, **서버 코드(`kiosk_server.py` 등) = tmux 안에서 Ctrl+C 후 재실행**,
    TTS 서버 코드(`tts_server.py`) = `pkill -f tts_server.py` 후 재실행(로딩 30초~2분).
  - 사용자가 띄워 둔 tmux 세션·서버를 임의로 종료하지 않는다. 재시작이 필요하면 사용자에게 알리거나 확인받는다.
- **마이크·스피커는 아직 보드에 연결된 장치만 쓴다**(노트북 음성 모드 미구현). 노트북 브라우저에서 마이크 버튼을 눌러도
  보드 마이크로 녹음되고, 로봇 음성도 보드 스피커로 나온다. 음성 검증은 "보드 앞 확인 필요"로 구분한다.
- 화면 확인은 헤드리스 크롬(`chromium-browser --headless … --screenshot`)으로도 보드 안에서 할 수 있다.

### 저장 위치 규칙 (엄수)
- 새로 만드는 파일·빌드 산출물·다운로드·가상환경·데이터셋·모델 파일 등
  **용량이 커질 수 있는 것은 전부 `/mnt/ssd` 아래에** 만든다.
- eMMC(`/`, `~` 직속, `/usr`, `/var` 등)에 큰 파일을 만들지 않는다.
- Python 가상환경은 `/mnt/ssd/projects/myproject/.venv`에 만든다.
- 대용량 작업 전에는 `df -h /`로 eMMC 여유를 먼저 확인한다.
  여유가 500MB 미만이면 멈추고 사용자에게 알린다.

## 2. 이 프로젝트의 워크플로우 (웹 ↔ VS Code)

이 프로젝트는 두 곳을 오가며 진행된다:

- **claude.ai 웹**: 기획·논의·설계 담당. 결과가 `PLAN.md`로 들어온다.
- **Claude Code (여기, VS Code/터미널)**: 실제 제작·설정·연동·실행 담당.

두 세계는 대화 기록을 공유하지 않는다. 아래 문서가 유일한 다리다:

- `PLAN.md` — 웹에서 넘어온 실행 대상. **작업 시작 전 반드시 읽는다.**
- `PROGRESS.md` — 실행 진행 기록. 작업할 때마다 여기에 append 한다.
- `HANDOFF.md` — 웹으로 넘길 요약. 작업 단위가 끝나면 여기에 작성한다.
- `CLAUDE.md` — (이 파일) 상시 맥락.

---

## 3. 작업 절차 (매 작업마다 따를 것)

사용자가 "구현해줘 / 실행해줘 / 만들어줘"라고 하면:

1. `CLAUDE.md`(이 파일)와 `PLAN.md`를 먼저 읽어 현재 목표와 제약을 확인한다.
2. 큰 작업이면 `df -h /`로 eMMC 여유를 확인한다. 산출물은 SSD 경로에 만든다.
3. `PLAN.md`의 체크리스트를 순서대로 구현한다. 완료 항목은 `- [ ]` → `- [x]`.
4. 한 항목이 끝날 때마다 `PROGRESS.md`에 "무엇을 했는지" 한 줄 로그를 append 한다.
5. 의미 있는 작업 단위가 끝나면 `git add -A && git commit` 한다.
6. 마지막으로 `HANDOFF.md`에 "웹에 넘길 요약"(한 것 / 남은 것 / 다음에 기획할 것)을 쓴다.

## 4. 커밋 / 안전 규칙

- 커밋 메시지는 짧고 명확하게. 형식 예: `feat: 로그인 폼 추가`, `fix: 경로 오류 수정`.
- 파괴적인 명령(`rm -rf`, 대량 삭제, 포맷 등)은 실행 전 사용자에게 확인받는다.
- eMMC를 채울 위험이 있는 작업(대용량 설치·다운로드)은 SSD 경로로 유도하고,
  불가능하면 사용자에게 먼저 알린다.
- `/mnt/ssd`가 마운트되어 있는지 의심되면 `df -h /mnt/ssd`로 확인 후 진행한다.
