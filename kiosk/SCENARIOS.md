# SCENARIOS.md — 병원 안내 로봇 시나리오 모음

> 이 문서는 로봇이 응대하는 **상황(시나리오)**들을 한 편의 대본처럼 적어 둔다.
> 시나리오 하나 = **손님 한 명의 완결된 여정** 하나.
> 새 시나리오는 아래 **템플릿**을 복사해 채운다. 이미 구현된 것은 ✅, 계획은 ⬜.

---

## 시나리오 작성 템플릿 (복사해서 사용)

```
■ 시나리오명:
■ 상태:            (✅ 구현됨 / 🚧 일부 / ⬜ 계획)
■ 목적·가치:
■ 대상(누가):
■ 트리거(무슨 말/상황으로 시작):
■ 사전조건(좌표·데이터가 필요한가):
■ 정상 흐름:
   1) 손님: "…"
   2) 로봇: (동작) + "…"
   3) …
■ 예외·분기:
   - (상황) → (대응)
■ 종료 조건:
■ 성공 기준(무엇을 보면 됐다고 하나):
■ 관련 파일/데이터:
```

## S-01. 진료과 위치 안내 (길안내) ✅

- **상태**: ✅ 구현됨 (현재 로봇의 핵심 기능)
- **목적·가치**: 방문객이 원하는 진료과/시설의 **위치를 알고**, 원하면 **로봇을 따라 그곳까지** 갈 수 있다.
- **대상**: 외래 환자·보호자·방문객. 한국어·영어·일본어·중국어 응대.
- **트리거**: 홈 화면에서 마이크 버튼을 누르고 `"○○ 어디예요"` 라고 말함.
  (마이크 없을 때는 개발용 `?dev=1` 화면에서 타자로 입력.)
- **사전조건**:
  - 해당 장소가 `locations.js`에 있어야 지도에 하이라이트된다.
  - 로봇이 실제로 **주행**하려면 그 장소의 목표 좌표(`/goal`)가 등록돼 있어야 한다.
    좌표 없는 장소(예: 영상의학과)는 위치 안내까지만 하고 주행은 막는다.
- **정상 흐름**:
  1. 손님: 마이크 버튼 누름 → 로봇: "말씀해 주세요" (안내 후 녹음 시작)
  2. 손님: "내과 어디예요"
  3. 로봇: (STT로 문장 인식 → 규칙 매칭, 실패 시 LLM 매칭으로 동의어·오인식·타국어 흡수)
  4. 로봇: 결과 화면 — 지도에서 해당 방을 빨갛게 표시 +
     "내과는 우측 복도 초입에 있습니다. 해당 위치로 안내를 시작할까요?" + [네] [아니오]
  5. 손님: [네]
  6. 로봇: 이동 화면 — 안내도 위 로봇 마커가 실제 진행률(남은 거리)로 이동
  7. 로봇: "도착했습니다" (약 5초 표시) → 홈 화면 복귀, 로봇도 초기 위치로 자동 복귀
- **예외·분기**:
  - **무음/인식 실패** → "잘 못 들었어요. 다시 말씀해 주세요." + [🎤 다시 듣기]
  - **저신뢰 매칭(0.5~0.85)** → "'내과' 말씀하신 게 맞나요?" + [네, 맞아요] [아니요, 다시]
  - **장소 못 찾음** → "어느 곳을 찾으시나요?" + 장소 버튼 목록에서 직접 선택
  - **목표 좌표 없음** → "…에 있습니다. 다만 아직 안내 준비 중입니다." + [네] 비활성화
  - **아니오** → 홈 화면 복귀
- **종료 조건**: 도착 후 자동 복귀, 또는 [아니오]/취소로 홈 복귀.
- **성공 기준**: 올바른 방이 하이라이트되고, 위치 문구가 맞고, (좌표가 있으면) 주행·도착까지 완료.
- **관련 파일/데이터**: `src/js/app.js`(흐름), `src/js/data/locations.js`(장소·좌표·다국어),
  `scripts/kiosk_server.py`(STT·매칭·`/goal`·`/nav`).

## S-04. 수속 안내 (초진/재진 + 환자 등록 + 증상 트리아지 + 대기명단) ✅ 구현됨

- **상태**: ✅ 구현됨 (환자 데이터셋·진료과별 대기명단 저장 포함).
- **홈 2단계 진입**: 홈에 "🧭 위치 안내" / "📋 접수 안내" 두 버튼만.
  위치 안내 → 마이크 등장 → 음성 장소 안내(S-01). 접수 안내 → 초진/재진 선택.
- **초진**: 이름·주민번호·연락처 입력 → 환자 데이터셋에 저장 → 증상 음성/타자 입력 →
  트리아지로 진료과 판단 → 그 **진료과 대기명단에 등록** → 위치 안내 제안.
- **재진**: 이름·주민번호 입력 → 조회 → 예약 여부 선택.
  예약함 → **이전 진료과** 대기명단에 자동 등록 / 예약 안 함 → 증상으로(초진과 동일).
- **데이터(서버 저장, SSD `data/`, 커밋 제외)**:
  - `patients.json` — {name, rrn_masked, rrn_hash, contact, history[], last_dept}.
    주민번호는 **평문 저장 안 함**(표시용 마스킹 `900101-1******` + 매칭용 sha256 해시).
  - `waitlist.json` — {진료과 id: [{name, rrn_masked, visit_type, symptom, added_at}]}.
- **관리자**: URL `?nurse=1`(예전 `?admin=1`도 호환) → 진료과별 대기명단 확인 화면(5초 자동 새로고침).
- **서버 엔드포인트**: `/patient/register`, `/patient/lookup`, `/waitlist/add`, `/triage`, `/waitlist`(GET).
- **미구현**: 실제 예약 시스템 연동(예약=이전 진료과로 근사), 대기명단 호출/삭제(등록만).

### (설계 원문 — 참고)
- **목적·가치**: 처음 온 사람도 **어디가 아픈지만 말하면** 알맞은 진료과를 골라 주고,
  **초진/재진·예약 유무**에 맞춰 접수 절차와 위치까지 이어서 안내한다.
- **대상**: 병원이 처음이라 어디로 가야 할지 모르는 방문객, 재진 방문객.
- **트리거**: "접수하고 싶어요" / "처음 왔어요" / "진료 보려면 어디로 가요" / "접수 어디서 해요".
- **사전조건 / 미결 사항**:
  - ✅ **접수 창구(원무과) 안내도 라벨 추가됨** — 진단검사의학과 오른쪽 옆 작은 방에 세로 라벨만 표기.
    로봇 초기 위치가 곧 원무과이고 안내 후 항상 이곳으로 복귀하므로, **목적지·위치안내 대상은 아님**
    (장소/매칭에서 제외). 손님은 처음부터 원무과 앞에 서 있는 셈 → "여기서 접수 후 ○○과로" 안내면 충분.
  - ⚠️ **예약 조회 시스템 없음**(추후 구현) — 재진 예약 확인은 손님에게 **진료과를 되묻는** 방식으로 처리.
- **증상 → 진료과 매핑(트리아지) 표** (직접 접수하는 진료과만; 영상/진단검사는 타과 의뢰라 제외):

  | 증상 예 | 추천 진료과 |
  |---|---|
  | 감기·발열·기침·소화불량·복통·만성질환(혈압/당뇨) | **내과** |
  | 베인 상처·외상·골절 의심·종기·탈장 | **외과** |
  | 임신·생리 문제·부인과 | **산부인과** |
  | 아이(영유아·청소년) 진료 전반 | **소아청소년과** |
  | 허리·목·관절 등 만성 통증·신경통 | **마취통증의학과** |

  → 이 매핑은 **LLM 매칭을 그대로 재사용** 가능(자연어 증상 → 진료과 id). 규칙+LLM 폴백.

- **정상 흐름**:
  1. 손님: "처음 왔는데 어디로 가야 해요?"
  2. 로봇: "처음 오셨나요, 이전에 오신 적 있으세요?" → **[초진]** **[재진]**
  - **[초진]**
    3. 로봇: "어디가 불편하세요? 증상을 말씀해 주세요."
    4. 손님: "머리가 아프고 열이 나요"
    5. 로봇: (증상→진료과) "말씀하신 증상은 **내과** 진료가 적합합니다.
       접수 창구에서 접수하신 뒤 내과로 가시면 됩니다. 내과 위치를 안내해 드릴까요?" → **[네][아니오]**
    6. [네] → **S-01 길안내(내과)** 로 합류
  - **[재진]**
    3. 로봇: "예약을 하고 오셨나요?" → **[예약함][예약 안 함]**
    - [예약함] → "어느 진료과 예약이세요?" → 확인 후 "○○과로 안내해 드릴까요?" → S-01 길안내
    - [예약 안 함] → 초진과 동일(증상→진료과→접수 안내→길안내)
- **예외·분기**:
  - **증상 모호/판단 어려움** → "정확한 과는 접수 시 안내받으실 수 있어요" + 진료과 버튼 목록(S-01 재사용)
  - **응급 의심 표현**(예: "숨을 못 쉬어요") → "증상이 급하시면 응급실이나 직원에게 바로 도움을 요청하세요"
  - **진료과 매핑 실패** → 장소 버튼 목록에서 직접 선택
- **종료 조건**: 진료과 길안내로 이어져 도착, 또는 접수 절차 안내만 듣고 종료.
- **성공 기준**: 증상만 말해도 알맞은 진료과를 추천하고, 초진/재진·예약 분기가 맞게 흐르며,
  마지막에 해당 진료과 위치 안내(S-01)로 매끄럽게 연결된다.
- **구현 방식(초안)**:
  - 진입점: 홈에 "접수·수속 안내" 경로 추가(음성 "접수" 발화 또는 버튼).
  - 새 화면/상태: 초진·재진 선택 → (재진) 예약 유무 선택 → 증상 입력.
  - 증상→진료과: 서버 매칭 로직 재사용(규칙+LLM). 필요 시 `/triage` 엔드포인트 또는 기존 `/listen` 확장.
  - 마지막은 기존 `showResult(진료과)`로 합류 → **길안내 로직 재사용**(중복 구현 없음).
- **관련 파일/데이터**: `src/js/app.js`(새 흐름), `src/js/data/locations.js`(진료과),
  `scripts/kiosk_server.py`(증상→진료과 매칭), (선택) 접수 창구 장소·좌표 추가.

## 다음 시나리오 후보 (backlog)

작성 우선순위 순. 각 항목을 위 템플릿으로 채우면 새 시나리오가 된다.

- ⬜ **S-02. 편의시설 안내** — 수납·원무·엘리베이터·카페·약국 등. **S-01과 동일 흐름**,
  `locations.js`에 장소+좌표만 추가하면 됨. → S-01의 가장 쉬운 확장.
- ⬜ **S-03. FAQ 응대(주행 없음)** — "진료시간 언제예요?", "주차 어디서 해요?", "면회 시간은?"
  같이 **말로만 답하는** 시나리오. 지도·주행이 없어 구현이 가볍다.
- ⬜ **S-05. 상황 대응 정교화** — 도움 요청, 반복 실패 시 직원 호출 안내 등 예외 흐름 강화.
- ⬜ **S-06. 대기 안내** — 예상 대기시간·순번(외부 데이터 연동 필요, 난이도 높음).

> 팁: 막막할 땐 **"이미 되는 걸 글로 옮기기"**(S-01)부터. 그다음 **가장 흐름이 같은 것**(S-02),
> **가장 구현이 가벼운 것**(S-03) 순으로 늘리면 부담이 적다.
