## 확정 사항 (웹 기획에서 결정)

- **안내도 소스는 `flat_map_labeled.png`로 확정.** 하이라이트 %좌표가 이 이미지 기준으로
  이미 검증되었으므로 소스를 바꾸지 않는다.
- **지도에 남아있는 빨간 경로 화살표는 제거한다.** 앱이 방을 빨간색으로 하이라이트하는데
  고정된 빨간 화살표가 함께 있으면 사용자가 혼동한다.
- **층 표기는 아직 미확정.** 단, 나중에 쉽게 바꿀 수 있도록 이번에 구조만 잡아둔다 (항목 1).

## 작업 체크리스트

### A. 정리 (작게 먼저)

- [x] 1. **층/장소 표기를 데이터 한 곳에서 관리하도록 분리한다.**
      현재 지도 이미지에 "1F" 표기가 구워져 있고 방 번호는 410번대라 서로 어긋난다.
      층 표기를 이미지에서 빼고 `locations.js`(또는 `config.js`)의 값으로 화면에 표시하게 바꾼다.
      → 나중에 층이 확정되면 데이터 한 줄만 고치면 되게 한다.
- [x] 2. 안내도에서 빨간 경로 화살표를 제거한 이미지를 만들어 교체한다.
      기존 파일은 남겨두고 새 파일로 만든다(되돌릴 수 있게).

### B. STT / LLM 연동

- [x] 3. **입력측 인터페이스(계약)를 먼저 정의한다.** 예:

      recognizer.listen() -> Promise<{
        text: string,            // 인식된 발화
        locationId: string|null, // 매칭된 장소 id (없으면 null)
        confidence: number       // 0~1
      }>

      `mockRecognizer`와 실제 구현이 **같은 계약**을 따르게 하고,
      설정값 하나로 목/실제를 전환할 수 있게 한다 (`USE_MOCK = true/false`).
      화면 코드(app.js)는 어느 쪽인지 몰라도 되게 유지한다.
- [x] 4. `stt_package`(오디오 → 텍스트)를 위 계약에 맞춰 연결한다.
      브라우저와 패키지 사이를 어떻게 잇는지(로컬 HTTP 엔드포인트 등)를 **먼저 조사하고,
      선택지와 근거를 사용자에게 보고한 뒤** 진행한다.
- [x] 5. `llm_package`(텍스트 → 장소/의도)를 연결한다.
      출력은 반드시 `locations.js`에 존재하는 장소 id로 매핑되게 한다(자유 텍스트를 그대로 쓰지 않음).
- [x] 6. **인식 실패 / 재질문 UX를 구현한다.** 최소 세 가지 경우:
      - 소리는 들렸으나 장소를 못 찾음 → "어느 곳을 찾으시나요?" + 예시 장소 버튼 표시
      - 신뢰도가 낮음 → "○○ 말씀하신 게 맞나요?" 확인 단계
      - 아예 인식 실패 / 타임아웃 → 다시 듣기 버튼
      실제 병원 환경은 소음이 있으므로 재시도가 쉬워야 한다.
- [x] 7. 목 모드(`USE_MOCK = true`)가 여전히 동작하는지 확인한다.
      실제 패키지가 없어도 예시 질문 칩으로 데모가 가능해야 한다(시연 대비).

### C. 좌표 변환 유틸 (ROS 대비, 이번엔 검증까지만)

- [x] 8. **안내도 좌표 ↔ 실제 맵 좌표 변환 함수를 만든다** (`js/utils/coordTransform.js` 등).
      기준 정보:
      - SLAM 맵: `my_map.pgm`, 원점 `[-39.2, -13.7]`, 해상도 `0.05 m/px`
      - ROS 맵 좌표 일반식: `world_x = origin_x + px * res`,
        `world_y = origin_y + (height_px - py) * res` (**y축 뒤집힘 주의**)
      - 안내도 이미지는 SLAM 맵과 별개로 그린 그림이므로,
        **기준점(anchor) 2~3곳을 잡아 축척·회전·평행이동(affine)을 맞춘다.**
- [x] 9. **로봇을 움직이지 않고 변환을 검증한다.**
      위치를 알고 있는 지점(예: 계단, 원무과 출입문) 2~3곳에 대해
      안내도 좌표 → 실제 좌표 변환 결과가 `my_map.pgm` 상의 실제 위치와 맞는지 대조하고,
      **오차를 미터 단위로 PROGRESS.md에 기록**한다.
      오차가 크면 원인(기준점 부정확 / 축척 오차 등)을 분석해 보고한다.
- [x] 10. `robotController.goTo(locationId)`가 내부적으로 이 변환을 거쳐
      **"실제 목표 좌표(x, y)"를 계산해 콘솔에 출력**하게 한다.
      실제 ROS 발행은 아직 하지 않는다 — 다음 사이클에서 이 자리에 끼운다.

## 제약 / 주의사항

- 모든 산출물은 `/mnt/ssd/projects/myproject/` 아래에. eMMC(`/`)를 채우지 않는다.
- 패키지 설치가 필요하면 **설치 전에 `df -h /`로 eMMC 여유를 확인**하고,
  용량이 큰 설치는 먼저 사용자에게 알린 뒤 진행한다.
- STT/LLM 연동 방식(항목 4)은 **바로 구현하지 말고 선택지를 먼저 보고**할 것.
- 각 항목이 끝나면 `- [x]` 표시 + PROGRESS.md 한 줄 기록 + 작업 단위마다 커밋.
